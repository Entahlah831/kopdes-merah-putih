1. Pengenalan & Pondasi Arsitektur Sistem

Kopdes Merah Putih adalah platform perbankan desa dan koperasi konsumen terdistribusi yang dirancang dengan standar keamanan tingkat tinggi (fintech-grade). Sistem backend dibangun menggunakan bahasa Golang dengan mesin basis data PostgreSQL 16.

5 Pilar Keamanan & Integritas Data Utama:
  1. Isolasi Multi-Tenant & RLS: Setiap query bisnis otomatis disaring oleh PostgreSQL FORCE ROW LEVEL SECURITY melalui session variable app.current_koperasi_id yang diekstrak murni dari token JWT (Mencegah kerentanan OWASP API1:2023 BOLA).
  2. Maker-Checker Guard: Pembuat transaksi/pembayaran dilarang memverifikasi pembayarannya sendiri (Pencegahan fraud internal pengurus).
  3. Anti-Float Financial: Seluruh perhitungan nilai uang menggunakan tipe data SQL NUMERIC(18,2) dan int64 di Go untuk mencegah selisih pembulatan sen.
  4. Append-Only Audit Journal: Tabel mutasi kas, log verifikasi, dan status dilarang keras di-UPDATE atau di-DELETE. Koreksi saldo wajib melalui entri reversal akuntansi.
  5. Kepatuhan UU PDP (UU No. 27 Tahun 2022): NIK, Tanggal Lahir, dan Nomor HP dienkripsi menggunakan AES-256-GCM dengan Blind Index HMAC-SHA256 untuk fitur pencarian cepat tanpa membuka plaintext.

Seluruh port server API maupun basis data dapat diubah secara bebas melalui file .env tanpa perlu melakukan kompilasi ulang pada kode program.

3. Panduan Fitur Pembayaran QRIS: Dua Model Pilihan

Kopdes Merah Putih menyediakan dua model adopsi QRIS untuk menjembatani kebutuhan antara tahap awal desa yang praktis tanpa izin rumit, hingga tahap modern koperasi skala besar.

MODEL 1 (Pilihan Saat Ini: QRIS Normal / Perorangan + Kode Unik Manual)

Mengapa Memakai Cara Ini? Anda tidak perlu menunggu pengurusan Akta Notaris Kemenkumham atau verifikasi rekening badan hukum bank yang memakan waktu berbulan-bulan. Anda bisa langsung memulai uji coba hari ini!

  1. Pendaftaran: Pengurus mendaftarkan QRIS perorangan milik bendahara/ketua (misal dari GoPay Merchant Mikro, Dana Bisnis, Livin Mandiri, atau BCA) via menu Admin.
  2. Pembuatan Tagihan: Anggota membuat tagihan (misal Iuran Rp 20.000). Sistem otomatis mengalokasikan 3-digit kode unik (misal 142) sehingga total transfer menjadi Rp 20.142.
  3. Pembayaran: Anggota memindai stiker fisik QRIS bendahara di kantor desa lewat m-banking apa saja (BCA, Livin, BRImo, Dana), lalu mengetikkan nominal pas Rp 20.142.
  4. Verifikasi: Bendahara melihat mutasi masuk Rp 20.142 di aplikasi HP miliknya, lalu mengklik tombol "Verifikasi Pembayaran" di sistem Kopdes.

MODEL 2 (Pilihan Otomatis: Dynamic QRIS Auto-Lock Nominal)

Bagaimana Cara Kerjanya? Algoritma backend di internal/qris/emvco.go secara otomatis mengubah payload QRIS menjadi QRIS Dinamis berstandar Bank Indonesia (PADG BI 21/18/PADG/2019):

  • Tag 01 diubah menjadi '12' (Dynamic Point of Initiation).
  • Tag 54 disuntikkan dengan total nominal pas (misal 20142).
  • Tag 62 disuntikkan dengan nomor invoice unik (misal PAY-886f-0300).
  • Tag 63 dihitung ulang checksum CRC16-CCITT False.

Hasilnya: Saat kode QR di layar HP atau web di-scan oleh anggota, layar nominal di aplikasi bank otomatis terkunci pada angka Rp 20.142. Anggota tidak bisa salah ketik nominal!

4. Modul Pendaftaran Anggota & Perlindungan Data Pribadi (UU PDP)

Sesuai mandat Undang-Undang No. 27 Tahun 2022 tentang Pelindungan Data Pribadi (UU PDP), sistem Kopdes Merah Putih menerapkan enkripsi dua lapis untuk seluruh data identitas warga desa:

Data Sensitif Metode Penyimpanan Tujuan & Implementasi
NIK (Nomor Induk Kependudukan) nik_enkripsi (AES-256-GCM)
nik_hash (HMAC-SHA256)		 Plaintext NIK tidak pernah tersimpan di database. Kolom hash berfungsi sebagai Blind Index agar pencarian tetap instan via indeks B-Tree tanpa perlu mendekripsi seluruh baris data.
Nomor Handphone no_hp_enkripsi (AES-256-GCM)
no_hp_hash (HMAC-SHA256)		 Melindungi nomor pribadi anggota dari kebocoran SMS/spam pemasaran ilegal.
Alamat & Tanggal Lahir alamat_enkripsi, tanggal_lahir_enkripsi Dienkripsi penuh menggunakan AES-256-GCM dengan nonce acak per record.

6. Panduan Praktis Integrasi Front-End (Web & Mobile)

Divisi Front-End memiliki kebebasan penuh dalam merancang antarmuka UI/UX. Berikut adalah modul siap pakai untuk menghubungkan aplikasi ke backend Go.

A. Modul Klien API (TypeScript / Fetch)

// lib/apiClient.ts
const BASE_URL = process.env.NEXT_PUBLIC_API_URL || "http://localhost:8080";

export async function kopdesAPI<T>(endpoint: string, options: RequestInit = {}): Promise<T> {
  const token = typeof window !== "undefined" ? localStorage.getItem("kopdes_token") : null;
  const headers = new Headers(options.headers || {});
  headers.set("Content-Type", "application/json");
  if (token) {
    headers.set("Authorization", `Bearer ${token}`);
  }

  const res = await fetch(`${BASE_URL}${endpoint}`, { ...options, headers });
  const json = await res.json();

  if (!res.ok || !json.success) {
    throw new Error(json.error?.message || "Terjadi kesalahan pada server");
  }
  return json.data;
}

B. Komponen Pembayaran QRIS (React / Next.js)

import React, { useState, useEffect } from "react";
import QRCode from "qrcode.react"; // npm install qrcode.react
import { kopdesAPI } from "../lib/apiClient";

export function PembayaranQRIS({ nominalDasar }: { nominalDasar: number }) {
  const [data, setData] = useState<any>(null);
  const [lunas, setLunas] = useState(false);

  useEffect(() => {
    // 1. Buat alokasi QRIS
    kopdesAPI("/api/v1/pembayaran/qris", {
      method: "POST",
      body: JSON.stringify({ nominal_dasar: nominalDasar, jenis_transaksi: "iuran_bulanan" })
    }).then(res => setData(res));
  }, [nominalDasar]);

  // 2. Polling status pelunasan setiap 4 detik
  useEffect(() => {
    if (!data || lunas) return;
    const interval = setInterval(async () => {
      try {
        const res: any = await kopdesAPI(`/api/v1/pembayaran/${data.pembayaran_id}`);
        if (res.status === "berhasil_diverifikasi") {
          setLunas(true);
          clearInterval(interval);
        }
      } catch (_) {}
    }, 4000);
    return () => clearInterval(interval);
  }, [data, lunas]);

  if (!data) return <p>Memuat QRIS...</p>;
  if (lunas) return <h2 style={{color: "green"}}>Pembayaran Berhasil Dikonfirmasi!</h2>;

  return (
    <div style={{ textAlign: "center", padding: "20px", border: "1px solid #ddd", borderRadius: "12px" }}>
      <h3>{data.nama_merchant}</h3>
      <QRCode value={data.qris_payload} size={240} level="M" />
      <h1 style={{ color: "#dc2626" }}>Rp {data.nominal_total.toLocaleString("id-ID")}</h1>
      <p>Kode Unik Transaksi: <b>{data.kode_unik}</b></p>
      <small style={{ color: "#666" }}>Nominal otomatis terkunci saat discan via m-banking</small>
    </div>
  );
}

7. Pertanyaan Umum & Troubleshooting (FAQ)

T: Mengapa login saya mendapatkan error 401 saat user baru dibuat?
J: Pastikan password yang dikirimkan cocok dengan password saat seeding, dan pastikan user tersebut telah dikaitkan dengan role di tabel user_roles untuk koperasi yang bersangkutan.
T: Apakah anggota wajib transfer menggunakan nominal pas beserta kode unik?
J: Ya, wajib. Jika anggota mentransfer tanpa kode unik (misal pas Rp 20.000 bukan Rp 20.142), sistem akan mendeteksi selisih bayar (selisih_bayar <> 0) dan admin harus melakukan penyesuaian manual di antrean verifikasi.
T: Bagaimana jika server PostgreSQL dipindahkan ke server lain?
J: Anda cukup mengedit file .env pada variabel DB_HOST, DB_PORT, DB_USER, dan DB_PASSWORD. Backend Go otomatis membaca konfigurasi baru tanpa kompilasi ulang.
